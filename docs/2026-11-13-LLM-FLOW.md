# LLM flow: how a question becomes an answer, and where a second model could plug in

_13 November 2026. Describes `backend/app/main.py` at v1.0.13. The second half is a proposal; none of it is built._

## 1. The flow today

There is exactly one model call per question. Everything before it is plain code and a small local
search model; everything after it is plain code.

```
  USER QUESTION  (+ session id, optional PDF or image)
        |
        v
+-------------------------------------------------------------+
| 1. ACT IN PLAY                     _act_in_play()           |   code only
|    Keyword match on Act names. A follow-up that names       |
|    sections but no Act inherits the Act from the last turn. |
+-------------------------------------------------------------+
        |
        v
+-------------------------------------------------------------+
| 2. LEGAL-QUESTION GATE             _is_legal_query()        |   code only
|    Regex. "hi", "thanks", "why can't you find it" stop      |
|    here and skip the search.                                |
+-------------------------------------------------------------+
        |                                   |
     legal                              not legal
        |                                   |
        v                                   |
+----------------------------------------+  |
| 3. SEARCH       search_similar()       |  |   local MiniLM model,
|    a. sections named by number         |  |   no outside call
|    b. pinned key sections for a topic  |  |
|    c. similarity search + keyword boost|  |
|    -> six excerpts                     |  |
+----------------------------------------+  |
        |                                   |
        v                                   v
+-------------------------------------------------------------+
| 4. BUILD THE PROMPT                _build_claude_messages() |   code only
|    system rules (about 10,000 tokens, fixed)                |
|    + "Acts Bowen holds" line + six excerpts + repeal notes  |
|    + earlier turns of this conversation + attachments       |
+-------------------------------------------------------------+
        |
        v
+=============================================================+
| 5. CLAUDE OPUS 5.5                 generate_response()      |   THE ONLY
|    Writes the answer and a final "SOURCES:" line naming     |   MODEL CALL
|    the excerpts it used. If it declines, Anthropic retries  |
|    on its fallback model inside the same call.              |
+=============================================================+
        |
        v
+-------------------------------------------------------------+
| 6. FINALISE                        finalise_answer()        |   code only
|    Strip the SOURCES line, match it to the six excerpts,    |
|    show only those as sources, add the "not held" footer    |
|    when nothing was cited, store the turn, log the query.   |
+-------------------------------------------------------------+
        |
        v
  ANSWER + SOURCES + DISCLAIMER
```

What leaves the server today: the question, the excerpts and any attachment go to Anthropic. Nothing
goes anywhere else.

## 2. Where a second model could plug in

Five places. Claude stays the writer of the answer in all of them.

```
  QUESTION
     |
     |<------------ [A] REWRITE / PLAN   turn the question into search terms,
     |                                   an Act and section numbers
     v
   SEARCH
     |
     |<------------ [B] RERANK           score 30 candidates, keep the best 6
     |
     |<------------ [D] OUTSIDE CONTEXT  web search for what the corpus lacks
     v                                   (case law, commencement, news)
   CLAUDE writes the answer
     |
     |<------------ [C] SECOND OPINION   a different model checks every claim
     |                                   against the excerpts
     v
   FINALISE
     |
     +<------------ [E] FAILOVER         answer from another vendor when
                                         Anthropic is down
```

**[A] Rewrite or plan the search**
- What it does: reads the question and the conversation, returns the Act, the section numbers and better search words
- Problem it fixes: 8 of 28 everyday questions missed the governing section in the 12 Nov evaluation; follow-ups search on the bare sentence
- Best model for it: Claude Haiku 5.5 (about $0.0002 a question). A second vendor adds nothing here
- Cost in time: about 1 second before the search
- Risk: low. A bad rewrite falls back to today's search

**[B] Rerank the candidates**
- What it does: the search fetches 30 excerpts, a model picks the 6 that answer the question
- Problem it fixes: split sections and near-miss Acts taking the six slots
- Best model for it: a dedicated reranker (Cohere Rerank, Voyage rerank) or Haiku. Not a chat model from OpenAI or Perplexity
- Cost in time: 0.3 to 1 second
- Risk: low

**[C] Second opinion on the draft**
- What it does: a model from a different vendor gets the excerpts and Claude's draft and lists any sentence the excerpts do not support, any wrong section number, any guess about a section not shown
- Problem it fixes: the rule 3 breaches in the ticket. A different vendor's model makes different mistakes, so it catches what a Claude checker would wave through
- Best model for it: OpenAI or Gemini. This is the one place a second vendor earns its keep
- Cost in time: 2 to 5 seconds, and it conflicts with streaming: the answer is already on screen before the check finishes. Either hold the answer until checked, or stream it and append a correction
- Risk: medium. False alarms; a second bill; the question and excerpts go to a second company

**[D] Outside context (Perplexity)**
- What it does: web search for things the corpus does not hold, such as case law, whether an amendment is in force, a regulator's guidance
- Problem it fixes: "Bowen holds only the Acts" answers
- Best model for it: Perplexity Sonar, or Claude's own web search tool, which does the same job with no second vendor
- Cost in time: 3 to 10 seconds
- Risk: high. It breaks the promise that every answer comes from the legislation Bowen holds. Web results would need their own clearly labelled block, never mixed into the cited answer

**[E] Failover**
- What it does: when Anthropic is unavailable, another vendor answers under the same rules
- Problem it fixes: outages
- Risk: high for little gain. The rules are tuned to Claude; another model has not been tested against them. A clear "try again shortly" is safer

## 3. Recommendation

1. Build [A] first, on Claude Haiku. It attacks the biggest measured fault (wrong or missing sections) for almost no cost, and needs no second vendor.
2. Then trial [C] with a second vendor, offline first: run the 28-question set, have the second model check Claude's answers, and count real catches against false alarms before it goes anywhere near users.
3. Leave [D] as a product decision for the trust, not an engineering one. It changes what Bowen claims to be.
4. Skip [E].

## 4. Things a second vendor changes regardless of where it plugs in

- Privacy: users' questions, and any attachment, would go to a second company. The privacy wording on the site would need checking and probably changing (not checked for this note)
- Keys and cost: a second API key in Railway, a second bill, a second rate limit
- Failure: every added call needs a timeout and a rule for what happens when it fails. The safe default is to carry on without it
- Testing: the offline test suite stubs Anthropic and blocks the network; a second vendor needs the same stub
